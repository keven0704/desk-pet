# 噜噜桌宠（Desk Pet）

一只趴在桌面上的水豚：点它一下截图圈题 → AI 给解题过程；也可以喊一句「噜噜，这个题怎么做」，它会自动截屏、弹出绿色框选，并把你说的话当成"补充描述"。想聊天就右键它 →「和噜噜聊天…」，陪聊心情、天气（会真的去查实时天气）和各种日常。

技术栈：Electron（桌面壳）+ Python/FastAPI（后端，负责调模型）+ WebSocket（前后端通信）。

---

## 一、环境要求

| 需要 | 版本 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 x64 | macOS 11+ / Linux 理论上可跑（`python3` 已做兼容），但未充分测试 |
| Python | 3.9+ | **只在「源码模式」和「编译后端 exe」时需要**；如果 `backend\deskpet-backend.exe` 已存在（一键打包产出的整包里就有），运行**完全不需要 Python** |
| Node.js | 20+ | **只在"从源码安装依赖"时需要**；拿到带 `node_modules` 的文件夹可以直接跑，不用装 Node |

> 给朋友用的推荐姿势：在你自己机器上跑一次 `打包给别人.bat`，生成的 `release\desk-pet.zip` 里**自带 Electron 和打包好的后端 exe**，朋友解压后双击 `启动桌宠.bat` 就能用，**Python / Node.js 都不用装**。

## 二、快速开始

### 1. 安装后端依赖（源码模式才需要）

```bash
pip install -r requirements.txt
```

> 如果项目里已经有 `backend\deskpet-backend.exe`（自己编译过，或收到的整包里带），这一步可以跳过。

### 2. 启动

| 方式 | 命令 | 适用 |
| --- | --- | --- |
| 双击启动（推荐） | `启动桌宠.bat` | 有打包好的后端 exe 时**不需要 Python**；没有则回退到源码模式（需要 Python） |
| 开发者 | `npm install` 然后 `npm start` | 已装 Node，首次会下载 Electron（约 100–200MB） |
| 手动分两个终端 | 终端1：`npm run backend`　终端2：`npm start` | 排查问题时最方便，能看到后端 + 桌宠的完整日志 |

> `npm start` / `启动桌宠.bat` 都会**自动拉起后端**：优先用 `backend\deskpet-backend.exe`，没有才用 `python -u backend/main.py`（Windows 会依次试 `python`、`py`；也可用环境变量 `DESK_PET_PYTHON` 指定解释器）。端口 8000 已有后端在监听则直接复用。

### 3. 配置 API Key（不配也能跑，进入演示模式）

右键桌宠或托盘图标 → **「API 设置…」**，填完保存**立即生效**（写进 `backend/.env`，并热更新到运行中的后端，无需重启）：

- **视觉（截图分析）**：智谱 `glm-4v-flash` 免费；硅基流动 `Qwen/Qwen2.5-VL-32B-Instruct` 部分免费
- **语音识别（唤醒 + 🎤 输入）**：硅基流动 `FunAudioLLM/SenseVoiceSmall` **免费**；智谱 `glm-asr` 按量计费（余额不足会返回 429/1113），OpenAI `whisper-1` 按量计费
- **噜噜的闲聊（第 3 栏）**：① **我所在的城市**（填了问「今天天气怎么样」就能查到实时天气）② **闲聊模型**（留空按服务商默认，如智谱 `glm-4-flash` 免费）

没配 Key 时是**演示模式**：截图分析返回示例文字；闲聊只回一句"还没接上大脑"；语音听不出内容，所以**不会自动唤醒**（避免没喊它也弹框），想看语音唤醒的完整流程请用「语音唤醒自检…」。

## 三、怎么用

- **左键点噜噜**：截屏 → 弹出绿色遮罩 → 拖一个框 → 回车分析（可先写/说补充描述）
- **拖拽噜噜**：移动位置；鼠标悬停会做小动作，托盘/右键菜单里有「投喂橘子」
- **语音**：说「噜噜，这个题怎么做」→ 自动截屏框选，**你说的那句话自动填进"补充描述"**
- **遮罩上**：回车 = 开始分析，Shift+回车 = 换行，Esc = 关闭；🎤 可以语音补充/追问
- **结果卡片**：文字可选中复制、可「继续追问」、有复制按钮
- **闲聊**：右键桌宠 / 托盘 →「**和噜噜聊天…**」打开陪聊小窗，聊心情、天气、日常（见下文）
- **托盘 / 右键菜单**：截图问一问、和噜噜聊天、语音唤醒自检、语音唤醒开关、投喂橘子、API 设置、开机自启动、退出

### 和噜噜聊两句（闲聊）

右键桌宠 →「**和噜噜聊天…**」（托盘里也有），弹出一个小聊天窗，跟豆包那种陪聊差不多：

- **能聊什么**：心情、天气、吃的、学习工作累不累、冷笑话…；让它解题/看屏幕它会提醒你圈题或点它截图（搜题那条链路不变）
- **它的人设**：噜噜是只**水豚（卡皮巴拉）**——情绪稳定、慢悠悠、爱泡澡晒太阳；语气词是「咕」「噜」「哼唧」（不是猫叫）。
  人设写在 `backend/main.py` 的 `CHAT_SYSTEM_PROMPT` 里，想换性格直接改那段
- **两种输入**：打字回车发送（Shift+回车换行），或点 🎤 说一句（说完再点一次结束，识别到的话就是你的发言）
- **聊天气**：先在「API 设置 → 噜噜的闲聊」里填**你所在的城市**，之后问「今天天气怎么样」会去
  `wttr.in` 查**实时天气**再回答（免费、不用 Key）；也可以直接问「北京今天冷不冷」。
  **查不到就如实说查不到**——不会编一个温度给你（没人希望被自己的桌宠骗）
- **记得上文**：最近约 10 轮对话会一起带上（关掉窗口再打开还能接着聊）；「清空」按钮 = 换个话题
- **不打扰搜题**：聊天窗口开着时会暂停「噜噜」语音唤醒监听（两个窗口同时开麦克风，聊着聊着遮罩会突然弹出来）
- **窗口位置**：自动贴在桌宠右边（放不下就左边），标题栏可以拖着走；整个界面点击、输入都正常（不是穿透窗口）
- **聊天记录只在内存里**：桌宠退出即清空，不写磁盘

> 闲聊用的是**纯文本模型**（默认按服务商预设：智谱 `glm-4-flash` 免费 / 硅基流动 `Qwen2.5-7B-Instruct`）。
> 想换模型：「API 设置 → 噜噜的闲聊 → 闲聊模型」填一个，或改 `backend/.env` 里的 `DESK_PET_CHAT_MODEL`。

### 喊「噜噜」没反应怎么查

> 一句话版：**先右键桌宠 →「语音唤醒自检…」，说一句「噜噜，这个题怎么做」**。
> 自检弹窗会直接告诉你两件事：① 它到底听到了什么字 ② 你说话的电平够不够触发——
> 不够的话它**会顺手把触发阈值按你这句话的电平校准**（"按说话电平校准触发阈值"），
> 再喊一次基本就好了（这类笔记本麦克风阵列增益很低、底噪读数是 0，
> 以前写死的 0.015 阈值很容易就把唤醒憋住）。

1. 右键桌宠 → **「语音唤醒自检…」**：录 4.5 秒，报告**识别文字 / 报错 / 这句的峰值电平 / 校准前后的阈值**
2. 右键桌宠 / 托盘 → **「查看语音唤醒日志」**：完整 `[wake]` 日志落在
   `%APPDATA%\desk-pet\wake.log`（**双击 `启动桌宠.bat` 启动时没有终端窗口，这是唯一能看到日志的地方**）：
   - `麦克风就绪：环境底噪 x → 触发阈值 y`：阈值自适应结果（底噪读数是 0 说明麦克风带噪声门，属正常）
   - `环境底噪几乎为 0（麦克风有噪声门）：阈值先用下限…`：等你说一句话来自动校准
   - `按说话电平校准触发阈值：峰值 0.0089 × 0.35 → 触发阈值 0.0031`：这次校准了
   - `连续 3 拍都在阈值以上…开始录音（含 xxxms 预录，唤醒词起头不会被切）`：监听期间一直有录音器在攒预录
     （VAD 认定"有人在说话"要 200~300ms，不预录的话"噜"字起头会被切掉，只剩一个"噜"就凑不成唤醒词）
   - `录音结束…送识别判断唤醒词` → `识别到「…」→ 含唤醒词`
   - `丢弃这段录音（… 太短 / 不够响）`：这段声音不够格，没送识别（也就不会被误唤醒）
   - `听到「卢鲁」像在喊唤醒词，但没匹配上（同音字没收录？）`：**链路是通的**，只是唤醒词表里没这个词，
     把这句发出来加进 `backend/main.py` 的 `WAKE_WORDS` 即可
   - `语音识别失败[no_speech]：这段录音里没检测到人声…（这段录音峰值 0.0xxx / 阈值 0.0yyy）`：
     这是**识别接口自己**没听出人声。录音峰值明显偏低就是麦克风增益问题（换/调麦克风）；
     电平够响还这样，说明识别模型不认这段音频，可以换个 ASR（「API 设置」里换硅基流动）
   - `疑似误唤醒…听音灵敏度系数 ×…`：遮罩被弹出来后又被立刻关掉，自动把灵敏度调低一档
   - `语音识别失败[insufficient_balance]`：ASR 没余额，去「API 设置」换成免费的硅基流动
3. 想单独量麦克风：`npm run test:mic`（说一句话，看各组约束下的 RMS 峰值；说话时只有 0.00x 就是麦克风增益太低）
4. 想跑完整链路（自检 → 校准 → 再喊一次）：`npm run test:wake`（对着电脑说两句，终端会打印全过程）
   > 没装 Node 的话，这两条等价于直接跑 `node_modules\electron\dist\electron.exe .mic-levels.js` / `.mic-test.js`
5. 即使语音完全不可用，**点噜噜手动框选**这条链路始终可用。

## 四、分享给别人（一键打包）

### 你只需要做一步

双击 **`打包给别人.bat`**（薄封装，真正的逻辑在 `pack-release.ps1`），它会自动：

1. 检查/编译后端 exe（没有就先调 `build-backend.bat`，会装 PyInstaller，约 1-2 分钟）
2. 把**根目录 + `backend\` + `assets\` 里的文件整体同步**到 `release\desk-pet\` —— 黑名单式：
   只排除与本机/VCS 有关的 `.env*`、`.gitignore`、`package-lock.json`、`*.log`，以及
   `build\`、`__pycache__\` 这类中间目录，所以源码里新加的脚本/回归测试（比如 `build-backend.bat`）
   会**自动跟着进包**，不会再出现「release 里少了某个文件」
3. 复制完立刻自检：关键文件（`启动桌宠.bat`、`build-backend.bat`、`backend\deskpet-backend.exe`…）
   缺一个就报错退出；**并全目录扫一遍 `.env`，只要出现就中止**（绝不带着你的 API Key 出包）
4. 顺带写一份 `第一次使用请看这里.txt` 给朋友
5. 复制 `node_modules`（Electron 运行时，约 250MB；`package.json` 没动过就直接复用上次那一份，省几分钟）
6. 压缩成 **`release\desk-pet.zip`**（150-200MB），再开包校验一次：条目数、关键文件都在、且不含 `.env`

把 `release\desk-pet.zip` 发给朋友即可。

### 朋友那边怎么做（真的只需一次双击）

1. 解压 zip
2. 双击 **`启动桌宠.bat`** → 桌宠出现（**不需要装 Python，也不需要 Node.js**）
3. 右键桌宠 →「API 设置…」→ 填**他自己的** Key（不填也能玩，是演示模式）
4. 用法：点一下噜噜 = 截屏圈题；说「噜噜，这个题怎么做」= 自动框选并把问题填进补充描述
5. 想聊天：右键桌宠 →「和噜噜聊天…」，可以聊心情、天气（在「API 设置 → 噜噜的闲聊」里填一下城市就能查实时天气）

### 想单独编译后端 exe

双击 `build-backend.bat`（或 `npm run build:backend`），产物是 `backend\deskpet-backend.exe`（约 31MB）。
编译需要在**你的**机器上装 Python + `pip install -r requirements.txt`；朋友那边不用。

> ⚠️ **改过 `backend/main.py` 之后一定要重新编译 exe**：桌宠启动时优先用 `backend\deskpet-backend.exe`，
> 只要它在，`main.py` 就完全不会被读到。旧 exe 遇到新功能（比如闲聊的 `chat` 消息）会回
> "未知消息类型"，聊天窗口会提示你重新编译（`build-backend.bat`），或者先退出桌宠再启动。

### 注意事项

- **别把 `backend\.env` 发出去**（里面有你的 Key；打包脚本已自动排除）。想手动打包的话，记得先删掉它。
- 整包里的 `node_modules`（Electron 运行时）**必须同操作系统同架构**：Windows 的包只能给 Windows 用。
- 打包出来的后端 exe 未签名，朋友首次运行可能被 SmartScreen / 杀软拦一下，选择"仍要运行"即可。
- 端口 8000 被占用时，让对方在 `backend\.env` 里加一行 `DESK_PET_PORT=8011`（前端会自动跟着换）。
- 想做成"安装包/免解压"体验，可以再上 `electron-builder`（本次未做）。


### 想做成"双击即用、不用装 Python"的成品

需要在原项目里再做两步（当前仓库未包含）：
- 用 **PyInstaller** 把 `backend/main.py` 打成 exe，让 `ensureBackendRunning()` 指向它；
- 用 **electron-builder** 打成安装包（`npm i -D electron-builder` + `build` 配置），把 exe/资源一起塞进去。

## 五、常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| 双击 `启动桌宠.bat` 一闪而过 / 桌宠冒泡"后端起不来" | 终端里会打印原因。源码模式最常见是没装 Python 或没 `pip install -r requirements.txt`；更省事的是双击 `build-backend.bat` 编译出 `backend\deskpet-backend.exe`，就不需要 Python 了 |
| 桌宠气泡提示"后端没有连接上" | 端口 8000 被占用或后端没起来。可在 `backend/.env` 里加一行 `DESK_PET_PORT=8011`（前端与后端都会读这个值）；或改用两个终端手动启动看报错 |
| 提示"没找到 Python" | 用 `build-backend.bat` 编译打包版即可完全绕开 Python；或装 Python 时勾选 *Add Python to PATH*，也可用 `DESK_PET_PYTHON=解释器路径` 指定 |
| 朋友解压后双击没反应 | 确认整包里存在 `backend\deskpet-backend.exe` 和 `node_modules\electron\dist\electron.exe`（用 `打包给别人.bat` 生成的一定有）；后端 exe 未签名时杀软/SmartScreen 可能拦一下，选"仍要运行" |
| `release\desk-pet` 里少文件，或打包时提示"打包不完整，缺少 xxx" | 打包脚本现在是**黑名单式同步**：根目录的文件默认全部进包，只排除 `.env*`、`.gitignore`、`package-lock.json`、`*.log` 这类本机/VCS 文件，所以在源码里新增的文件（新脚本、新回归测试）会自动进包。报"缺少 xxx"就是源码里那个文件真的不在了（被删/改名/大小写不符），补回来再打包 |
| 语音唤醒完全没反应 | 见上文「喊『噜噜』没反应怎么查」；另外确认系统里麦克风没被静音/被别的软件独占 |
| **没喊它也会被自动唤醒** | 已经做了 8 层收紧：① 唤醒词必须在**句子开头**附近（"我在看录录的视频"这类正文里的同音词不会再触发）；② 连续 3 拍（约 300ms）都过阈值才算"有人在说话"，键盘、关门、风扇这种"一下就没"的噪音不会起录音；③ 录音峰值要 ≥ 阈值×1.5 才送去识别，只是勉强擦过阈值的背景音（外放视频、空调）直接丢掉；④ VAD 阈值下限 0.006、按底噪×3 自适应（**2026-09 从 0.015 降下来**：实测笔记本麦克风阵列正常说话只有 0.006~0.008，0.015 那条线根本踩不到，是"喊他没反应"的主因）；⑤ **说话电平自学习**：自检/被丢弃的真实录音会按"峰值×0.35"把阈值往下校准（只降不升），低增益麦克风也能唤醒；⑥ **演示模式（没配 Key）不再自动唤醒**；⑦ **误唤醒自愈**：语音唤醒弹出来的遮罩如果 3 秒内被关掉、也没框选，就当成一次误唤醒，自动把听音灵敏度调低一档（终端打印"疑似误唤醒：听音灵敏度系数 ×…"），托盘里关掉再打开「语音唤醒"噜噜"」即可复位；⑧ 框选遮罩弹出时会真的暂停监听（以前那条消息发错了通道，麦克风一直在听，会被自己听到的声音反复惊动）。另外每次唤醒桌宠会冒泡 `听到「…」`，终端/日志也会打印 `识别到「…」→ …`，一眼就能看出是什么触发的：识别到的词不对就把那句发出来加进唤醒词表；确实不想要就右键桌宠 → 取消勾选「语音唤醒"噜噜"」 |
| 喊「噜噜」没反应 / 感觉它听不见 | 先右键桌宠 →「语音唤醒自检…」（会报告识别文字 + 说话电平，并按你的电平校准阈值），再用「查看语音唤醒日志」（`%APPDATA%\desk-pet\wake.log`）看 `[wake]` 全过程；想单独量麦克风用 `npm run test:mic` |
| 唤醒后要等十几秒才弹框选 | 已修：以前"说完"的判定线写死 0.004（比新阈值还高），房间底噪压不下去时会一路录到 10 秒上限再发识别。现在改成跟本段峰值走（阈值×0.5 与 峰值×0.25 取大者），说完约 1.4 秒就送出去 |
| 它听到了但识别成乱七八糟的字 / 报"没检测到人声" | 已经做了两件事：① 监听期间常驻录音器攒 1.5 秒预录，唤醒词起头那 200~300ms 不再被切掉（以前"噜噜"常被切成一个"噜"，凑不成唤醒词就被忽略）；② 送去识别前把录音**电平归一化**（只放大、最多 8 倍），笔记本麦克风那种 0.01~0.02 的小声音也能被听清。仍不行就换免费的硅基流动 SenseVoiceSmall 试试 |
| 气泡显示不全 / 文字被裁掉 | 气泡现在显示在**独立的气泡窗口**里（`bubble.html`，460x150，紧跟宠物头顶，离开时会自动收起）：以前气泡画在 200x200 的桌宠小窗里，宠物头顶只剩 52px，两行以上的文案会被窗口上边缘切掉。气泡窗口整个是"点击穿透"的，不挡桌面点击也不抢焦点；超过 80 字的文案由 `main.js` 先截断（气泡最多约 6 行） |
| 语音识别报 429 / 余额不足 | 智谱 `glm-asr` 是收费模型，换「硅基流动 SenseVoiceSmall（免费）」或充值 |
| 截图框选位置偏了 | 已按 DPI 缩放系数与显示器原点换算；若多显示器仍异常，把「显示器缩放」和分辨率发出来 |
| 首次启动 Windows 弹 SmartScreen / 请求麦克风权限 | Electron 未签名的正常提示，允许即可 |
| 想换模型/服务商 | 「API 设置」里选服务商，视觉与语音识别分别可配；自定义服务商填 OpenAI 兼容地址 |
| 聊天窗口一直显示"正在想" / 提示"后端好像不认闲聊请求" | 跑着的后端是**旧版**：桌宠优先用 `backend\deskpet-backend.exe`，`main.py` 的改动它读不到。退出桌宠 → 双击 `build-backend.bat` 重新编译 → 再启动；不方便编译就把 `backend\deskpet-backend.exe` 改名/删掉，退回源码模式（需要 Python） |
| 问天气答"查不到" / 说了个别的城市 | 先在「API 设置 → 噜噜的闲聊」填**你所在的城市**；也可以直接问「北京今天冷不冷」（它会把城市从句子里挑出来）。实在查不到通常是 `wttr.in` 连不上（公司网络/代理），它**不会编温度**，只会如实说查不到 |
| 闲聊太啰嗦 / 模型不对 | 「API 设置 → 噜噜的闲聊 → 闲聊模型」换一个（默认智谱 `glm-4-flash` 免费、硅基流动 `Qwen2.5-7B-Instruct`）；人设（水豚性格、语气、长度）写在 `backend/main.py` 的 `CHAT_SYSTEM_PROMPT` 里，想改直接改 |
| 聊天记录会保存吗 | 不会落盘：只在内存里，关掉窗口再打开还能接着聊，桌宠退出就清空 |

## 六、目录结构

```
desk-pet/
├─ main.js            # Electron 主进程：窗口、托盘、截屏、WebSocket、语音唤醒调度、后端拉起
├─ preload.js         # 渲染进程与主进程的 IPC 桥（petAPI / overlayAPI / chatAPI）
├─ pet.html / pet.js  # 桌宠本体：动作、麦克风监听 + VAD + 唤醒词流程（气泡不画在这儿）
├─ bubble.html        # 气泡窗口的页面：只显示一句话，窗口点击穿透、紧跟宠物头顶
├─ overlay.html/.js   # 全屏框选遮罩、补充描述输入、AI 结果卡片与追问
├─ chat.html / chat.js # 闲聊窗口：气泡列表 + 输入框 + 🎤，右键「和噜噜聊天…」打开
├─ settings.html/.js  # 「API 设置」窗口（视觉 + 语音识别 + 噜噜的闲聊）
├─ voice-utils.js     # 录音(WebM/MP4) → 16kHz 单声道 WAV（后端 ASR 用）
├─ assets/pet.png     # 桌宠贴图
├─ backend/
│  ├─ main.py         # FastAPI + WebSocket 后端：视觉分析、闲聊(人设/天气)、ASR、唤醒词检测
│  ├─ deskpet-backend.exe  # 编译出的独立后端（build-backend.bat 生成）：有它就不需要 Python
│  ├─ _prompt_test.py # 调试脚本：造一张数学题图，直接调 crop_region + analyze_screenshot 看返回
│  ├─ build/          # PyInstaller 中间产物（可删）
│  └─ .env            # API 配置（**分享前删掉**；打包脚本会自动排除）
├─ requirements.txt   # 后端 Python 依赖（源码模式用）
├─ 启动桌宠.bat        # 一键启动（自动判断用打包版还是源码模式）
├─ build-backend.bat   # 把后端编译成独立 exe
├─ 打包给别人.bat      # 一键打包（薄封装，真正的逻辑在 pack-release.ps1）
├─ pack-release.ps1    # 打包逻辑：复制文件 → 校验 → 压缩成 release\desk-pet.zip
└─ .asr-error-test.py  # 回归测试：ASR 错误分类 + 唤醒词匹配（python .asr-error-test.py）
   .chat-test.py       # 回归测试：闲聊人设/天气意图/城市解析/消息组装/演示模式（python .chat-test.py）
   .exe-test.py        # 回归测试：编译出的后端 exe 能起、能读 .env、能连 WS（python .exe-test.py）
   .pet-test.js        # 回归测试：气泡显示、唤醒 VAD 判定、阈值自学习（npm run test:pet）
   .chat-test.js       # 回归测试：闲聊窗口渲染、流式回复、失败提示、IPC 通道（npm run test:chat）
   .mic-levels.js      # 体检工具：量默认麦克风各约束下的电平（npm run test:mic）
   .mic-test.js        # 体检工具：真实麦克风跑完整唤醒链路，打印 [wake] 全过程（npm run test:wake）
   .api-debug.py       # 调试脚本：用一张 1x1 假图直连 analyze_screenshot，看真实 API 返回（python .api-debug.py）
   .prompt-test.py     # 调试脚本：Pillow 画一张"鸡兔同笼"题图，走完整「框选→分析」链路看回答（python .prompt-test.py）
   .layout-test.js     # 调试脚本：离线验结果卡片的换行/高度/滚动布局（node .layout-test.js）
```

> `release\desk-pet\`（`打包给别人.bat` 的产物）就是上面这份目录：**根目录、`backend\`、`assets\`
> 里的文件一个不落地同步过去**（只去掉 `.env*`、`.gitignore`、`package-lock.json` 这类本机/VCS 文件，
> 以及 `build\`、`__pycache__\` 中间目录），再加上 `node_modules` —— 以后在源码里新增文件，
> `打包给别人.bat` 会自动把它带进包。

> 编码约定：`.bat` 用 GBK（中文 Windows 双击时显示正常），`.ps1` 用带 BOM 的 UTF-8。
> 如果你用记事本/编辑器改这些脚本，请保持原编码，否则中文提示可能变乱码（功能一般不受影响）。
